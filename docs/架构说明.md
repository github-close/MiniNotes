# MiniNotes 架构说明

## 项目概述

Windows 托盘常驻极简便签工具。全局热键 / 点击托盘图标唤起，失焦自动隐藏；「待办」页（勾选列表）+「笔记」页（左列表 + 右编辑器）。数据为便携式纯文件（exe 旁 `data/` 下 `notes/*.md`、`notes.order`、`notes.pinned`、`todos.json`、`config.ini`），无数据库、无 WebView。设计目标：单 exe（约 220KB）、常驻私有内存约 4MB。支持浅色 / 暗色 / 跟随系统三档主题。

## 技术栈

- **Rust 1.97+**（`x86_64-pc-windows-msvc`），构建需 MSVC 链接器，无其他运行时依赖
- **windows-sys 0.52**：直调 Win32 API（仅编译期声明，不引入运行时）。已知特点：
  - 句柄（`HWND` 等）是 `isize` 不是指针；GDI+ 的 `GpGraphics` 等是裸指针
  - 常量类型混杂：`WS_*`/`BS_*`/`ES_*` 有 `u32` 也有 `i32`，组合时常需 `as u32`
  - 模块归属反直觉：`SetFocus`/`VK_*`/`TrackMouseEvent` 在 `Input::KeyboardAndMouse`，`WM_MOUSELEAVE`/`DRAWITEMSTRUCT`/`SetWindowTheme` 在 `UI::Controls`
  - 控件宏（如 `ListView_SetCheckState`）不存在，用 `LVM_*` 消息手写；`EM_SETCHARFORMAT`/`CHARFORMATW` 缺失（已弃用 RichEdit，改用标准 EDIT）
- **GDI+（flat API）**：圆角矩形、抗锯齿勾选框图标的绘制（`theme.rs`），内存开销约 +1MB
- **serde / serde_json**：仅用于 `todos.json` 持久化
- **winres**（build-dependencies）：编译期嵌入图标 + manifest（Common-Controls v6 + DPI aware）
- Release profile：`opt-level="z"` + LTO + `panic="abort"` + strip，产物约 220KB

## UI 架构（主题化）

- **无边框窗口**：样式为 `WS_THICKFRAME|WS_SYSMENU|WS_MINIMIZEBOX|WS_MAXIMIZEBOX`（无 CAPTION），`WM_NCCALCSIZE` 返回 0 去掉非客户区——DWM 阴影、边缘拖拽调整大小、Win+方向键贴靠全部保留。注意：创建期间收到的 NCCALCSIZE 的 wParam 可能为 0，且这条消息必须在 App 就绪前就处理，否则系统边框永久残留。最大化时系统给的窗口矩形是「工作区四周各大一圈边框」（实测各 8px，左/上为负坐标），返回 0 会把这一圈也当成客户区、内容被屏幕边缘裁掉，因此最大化时客户区要按 `SM_CXSIZEFRAME + SM_CXPADDEDBORDER` 内缩回去
- **自绘层次**：标题栏（图标+标题+热键提示+关闭钮）、Tab 药丸、输入框描边都画在主窗口 `WM_PAINT`（内存 DC 双缓冲防闪烁）；按钮全部 `BS_OWNERDRAW` + 子类悬停跟踪（`theme::draw_button`，Primary/Tonal 两种）；列表行 `NM_CUSTOMDRAW` 返回 `CDRF_SKIPDEFAULT` 完全自绘（选中淡底圆角 + `ImageList_Draw` 图标 + 文字，内联重命名时交还系统）
- **勾选框图标**：本机 ImageList 不支持 alpha/mask 透明（全画成黑色不透明块，DIB 全零也一样）——因此图标不透明，背景色直接用行背景色（视觉无缝）。圆圈/对勾由 `assets/brand/make_todo_checkboxes.py` 离线烘焙（4 倍超采样几何原语绘制 + LANCZOS 降采样，边缘抗锯齿平滑；逐像素距离数学的旧画法已废弃），输出 72×26 图标条 bin（3 格：纯背景/未完成/完成，浅暗主题各一份，色板常量与 theme.rs 同步），运行时 `make_checkbox_imagelist` 一次 `CreateDIBSection + memcpy + ImageList_Add`，ImageList 按 cx=24 自动切格。这套「离线烘焙 + 运行时贴 bin」与设置页 logo、笔记列表置顶图钉同一模式
- **字体分工**：`Microsoft YaHei UI`，编辑器/输入框/笔记列表 12px（`util::create_ui_font`），待办列表正文 13px（`App.font_todo`，与 Tab 字号一致更舒展，行内编辑按目标列表跟随），标题/Tab 13px 半粗（`create_font_title`）；高度传负值 = 字符高度不含行距
- **编辑器是标准多行 EDIT**（不是 RichEdit）：主题化走 `WM_CTLCOLOREDIT` 现成链路（RichEdit 不响应且其专属消息在 windows-sys 缺失）。EDIT 只认 CRLF：读文件 LF→CRLF，保存 CRLF→LF，`EM_SETLIMITTEXT` 放开 32K 上限
- **主题三档**：`theme=light|dark|system`（config.ini），system 读注册表 `AppsUseLightTheme`；`WM_SETTINGCHANGE` 时跟随系统档自动切换；`apply_theme` 重建画刷/图标列表并刷新全部控件
- **系统暗色开关**：comctl32 的 `DarkMode_Explorer` 主题（列表底色/滚动条/EDIT 光标）只有在 uxtheme 内部的暗色模式打开后才真正用暗色渲染——`theme::set_system_dark` 通过未公开序号函数（132/135/136：RefreshImmersiveColorPolicyState / SetPreferredAppMode / FlushMenuThemes）按应用解析出的主题强制亮或暗。这些 API 是 Windows Terminal 等一线应用长期使用的非官方接口，Win10 1809+ 稳定；序号缺失（老系统/精简系统）时整体优雅降级。`apply_theme` 切主题时同步调用，使列表、编辑器滚动条、输入框光标全部跟随
- **列表暗色补丁**：主题列表自身底色与窗口底色存在色差（暗色下透出来像一块凸面板），补丁分三层：①列表子类接管 `WM_ERASEBKGND` 用窗口底色擦除（BeginPaint DC 自带裁剪，安全）；②每个行在 `CDDS_ITEMPREPAINT` 里先填行底再画内容（选中胶囊/文字/勾选图标），行内自洽；③`CDDS_POSTPAINT` 盖掉主题在最右列边缘画的 1px 装饰线。**切忌在 `CDDS_PREPAINT` 铺整个客户区**：列表局部重绘（点击选中只重绘受影响行、勾选切换 LVM_REDRAWITEMS 单行）走的 DC 无裁剪，整客户区填充会把未重绘的行全部擦没——表现为"列表行突然消失，只剩刚交互过的那行"（实测踩过）。列表子类同时接管 `WM_CTLCOLOREDIT`：内联重命名编辑框挂在列表下，CTLCOLOR 消息由列表收到，不接管则系统兜底成白底黑字；编辑框创建时挂 `DarkMode_Explorer` 让光标在深底上可见
- **自绘弹出菜单**：Win10 的原生菜单（`TrackPopupMenu`）配色跟随**系统**的「应用深色」设置（AppsUseLightTheme），进程级 uxtheme 开关管不到它——应用设为暗色而系统为亮色时菜单仍是白色（本机实测确认）。因此列表右键与托盘菜单全部改用 `menu.rs` 自绘：与应用同色板的弹出窗、`SetCapture` 接管鼠标（悬停高亮/点击选中/点外取消）、`MsgWaitForMultipleObjectsEx + PeekMessage` 模态循环返回选中命令 id（语义等同 `TPM_RETURNCMD`，WM_QUIT 照原生菜单回贴主循环）。锚点取 `GetCursorPos`，底部放不下时向上翻转贴住光标（托盘菜单的正确位置）。七个坑（每个都实测踩过）：
  ①行布局累加器与窗口锚点 Y 是两个变量，混用会把菜单放到「y=内容高度」的屏幕顶部；②`show` 不可重入——菜单开着再触发会覆盖 static 状态，入口先销毁旧菜单，模态循环退出清理时按 hwnd 识别归属，`menu_with` 对缺失状态返回默认值而非 panic；③**SetCapture 只对前台窗口完全生效**（MSDN），后台窗口的捕获仅覆盖自己可视区上方——菜单必须自己 `SetForegroundWindow`（即原生托盘菜单「弹菜单前激活自己，否则菜单不消失」的经典套路），激活转移导致的 owner 失焦由 `should_skip_auto_hide` 的 PID 判定兜住；④`WM_CAPTURECHANGED` 有两个来源，处理器必须用 closing 守卫区分：(a) 用户点击其他进程窗口时系统强制收回捕获（点击照常送达对方），菜单只收到这一条消息——不自行退出就永远留在屏幕上；(b) 自身 dismiss 的销毁流程释放捕获也会同步产生它——这条不得清零 result，否则点中菜单项会被抹成"取消"，表现为"菜单关了但命令不执行"；⑤**捕获期间系统不发 `WM_SETCURSOR`**（该消息仅限未捕获状态），光标会停留为上一个窗口的形状（如文本工字形）——`WM_MOUSEMOVE` 里自己 `SetCursor(箭头)`，捕获下菜单能收到全屏移动，效果与原生菜单一致；⑥销毁带捕获的窗口会同步产生 `WM_CAPTURECHANGED`，dismiss 用 closing 标志防重入；⑦菜单激活期间焦点在菜单上，`WM_KEYDOWN` 处理 Esc 关闭；关闭时若菜单仍是前台且 owner 可见则把前台还给 owner（用户点了其他程序时不抢回）
- **设置对话框**：checkbox 与单选钮的图形保留系统主题绘制（暗色挂 `DarkMode_Explorer`），文字一律由 STATIC 承担（系统自绘的按钮文字颜色不可控，暗色下会隐入背景；SS_NOTIFY 让点击文字也能切换）；标题栏暗色用 `theme::allow_dark_chrome`（uxtheme 序号 + `DWMWA_USE_IMMERSIVE_DARK_MODE`，旧版本自动回退属性 19）。**守卫必须先于 EnableWindow**：`settings::open` 若先 `EnableWindow(owner, 0)` 再置 `settings_open`，禁用前台主窗口的瞬间系统会收回前台、主窗口收到 `WM_ACTIVATE(0)`，失焦隐藏在守卫生效前就把主窗口藏回托盘（关闭设置后窗口"凭空消失"）

## 关键设计决策（为什么是这样）

### 为什么用裸指针而不是 RefCell 保存全局状态

Win32 消息机制是重入的：在处理某条消息时调用 `SendMessageW`，会同步进入 wndproc 处理新消息。如果用 `RefCell<Option<App>>`，外层闭包还持有可变借用时内层再 `with_app` 就会双重借用 panic（实际踩过：`todos::rebuild` 持有借用 → `SendMessageW` → wndproc → `with_app` → panic）。

因此 App 状态用 `static mut` 裸指针保存（UI 单线程，等同 C 的 GWLP_USERDATA 模式），一律通过 `with_app(|app| ...)` 访问。

### `Option<Box<App>>` 禁止 `.read()`

`ptr::addr_of!(APP).read()` 会按值拷贝出临时 `Option<Box>`，临时值离开作用域时 Box 被误 drop，堆上的 App 被释放——之后所有堆操作都会检测到损坏（c0000374 崩溃的根源）。正确写法：`(*addr_of_mut!(APP)).is_some()`。

### match 里的常量必须真的导入

settings.rs 曾漏导入 `WM_CTLCOLOREDIT`/`WM_CTLCOLORSTATIC`，Rust 把 match 臂当成通配符绑定（新 catch-all），吞掉后续所有臂且行为诡异。编译器会报 `unreachable_patterns` 警告——看到这类警告务必当 bug 处理。

### 热键注册失败不阻塞启动

全局热键可能被其他程序占用。注册失败时自动依次尝试备选组合（Ctrl+Alt+N → Alt+Q → Ctrl+Alt+Q），成功后写回 config 并用托盘气泡告知用户；全部失败也只气泡提示，不弹阻塞对话框。

### 数据损坏不覆盖

`todos.json` 读取或解析失败时，先把原文件改名为 `todos.json.bak` 再以空列表启动。否则后续任意一次新增/勾选都会把空列表写回去，用户原始数据就没有了。

### 列表排序与置顶

笔记列表的显示顺序由三元排序键决定：`(是否未置顶, 顺序文件位置, mtime 倒序)`。`notes.order` 记录手动拖拽顺序（一行一个文件名，refresh 时回写清理已删条目、补录外部新增文件）；`notes.pinned` 记录置顶名单（同格式），置顶笔记固定排在最前，组内仍按手动顺序。

置顶与拖拽的边界约定：置顶笔记只能在置顶区内拖动，未置顶笔记只能在未置顶区内拖动。`reorder` / `drag_drop_index` 的落点索引与 `drag_line_y` 的插入线位置都按置顶区边界（`pinned_count`，refresh 排序保证置顶总在前缀）做同一规则的 clamp，越界的落点收拢到边界上，插入线画在置顶区底缘而不是指向对方区域内部。

置顶 / 取消置顶（`notes::toggle_pin`）：置顶时文件名同时插入 `notes.pinned` 与 `notes.order` 首位（跳到列表最顶，且最新置顶的排最上）；取消时仅移出置顶名单，手动顺序保留（自然落回未置顶区首位）。重命名时 `apply_rename` 同步改写两个文件里的旧名字——漏掉顺序文件会被当作外部新文件追加到末尾，漏掉置顶名单会在下次 refresh 残留清理时静默丢失置顶状态。

### 隐藏即保存

窗口隐藏（失焦自动隐藏 / Esc / WM_CLOSE / 最小化）和 WM_DESTROY 时：保存当前笔记、窗口位置尺寸、当前 Tab、当前笔记名到 `config.ini`。下次唤起恢复原状态。最小化/最大化状态下的窗口矩形不是用户摆放的正常尺寸（最大化时甚至落在屏幕外），这两种状态不写位置尺寸，保留上一次正常状态的值；唤起时若窗口处于最小化，用 `SW_RESTORE` 还原而不是 `SW_SHOW`（后者对最小化窗口只是「按原状态显示」，屏幕上仍看不到）。
